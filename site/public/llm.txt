# Monorepo Skills

monorepo-doctor audits JS/TS workspaces and performs limited static Bazel
visibility and test-only dependency checks, including in standalone Java
workspaces. Bazel support is partial: it does not analyze Java source cycles,
Bazel caching or CI coverage. The audit requires Node.js but does not require
npm or Bazel to inspect a standalone Bazel workspace.

- Bazel reference: https://monorepo-skills.dev/skills/monorepo-doctor/references/bazel.md
- Bazel Java example: https://github.com/santoshyadavdev/monorepo-doctor/tree/master/examples/bazel-java
- Getting started: https://monorepo-skills.dev/getting-started/#try-the-bazel-examples

polyrepo-tax prices what splitting code across several repositories costs:
bugs attributable to repo boundaries (with confidence and commit evidence),
developer and CI time spent on internal bumps, releases, coordinated changes
and repeated maintenance, converted to a low/expected/high money range. It
plans a monorepo migration only for coupled repos that pay it back, and says
not to migrate otherwise. It is read-only and writes HTML, Markdown and JSON.

- Skill: https://monorepo-skills.dev/skills/polyrepo-tax/SKILL.md
- Walkthrough: https://monorepo-skills.dev/guides/polyrepo-to-monorepo/
- Sample report: https://monorepo-skills.dev/sample-reports/polyrepo-tax/
  (HTML: https://monorepo-skills.dev/examples/polyrepo-tax-report.html,
  image: https://monorepo-skills.dev/examples/polyrepo-tax-report.png)
